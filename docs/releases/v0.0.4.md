# omd v0.0.4

Fourth release of **oh my day**, a local-first notebook. Changes since v0.0.3:

- **Independent browser tabs:** each tab keeps its own selected page while
  notebook edits continue to synchronize through IndexedDB and BroadcastChannel.
  Selecting a page no longer changes the content revision or undo history.
- **Page links:** every page has a stable `/page/:id` route (`/omd/page/:id` on
  the hosted app). Copied links, refresh, browser Back/Forward and opening page
  links in a new tab retain the selected page, including subpages.
- **Safe navigation:** pending edits save before switching pages. Missing,
  deleted or replaced page IDs fall back to an existing page with a notice,
  without creating a fake page or redirecting edits to another page.
- **Deep-link hosting:** the local launcher serves page document routes, the
  build includes a GitHub Pages `404.html` fallback, and the service worker can
  reopen page links offline. Missing script/style assets remain errors.
- **Editable tables:** insert and remove rows or columns, edit cells, pin headers
  and leading columns, and navigate the grid with keyboard or touch controls.
- **Tabs and checklists:** drag tab headers to reorder them and rename tab titles
  inline. Checklist items now support Markdown without a formatting toolbar,
  including nested items, links, lists and paste.
- **Fast text input:** Shift+Enter focuses the next text editor immediately so
  fast typing cannot split text between blocks while storage is saving. IME,
  caret and draft text remain in the same editor; failed insertion offers retry.
- **Preserved storage recovery:** native v4 startup validates every page's
  metadata before loading content. Failed startup releases database connections
  and history leases, while malformed saved data and recovery backups remain
  intact for explicit recovery.
- **Patched dependencies:** tested Nanoid, KaTeX, lodash-es and Sass updates,
  with a reproducible dependency lockfile, reduce the verified installation's
  npm audit report from 14 affected package entries to zero. Packaged dependency
  inventories, third-party notices and checksums reflect the updated bundle.

Existing IndexedDB databases upgrade atomically to schema v4, preserving notebook
data, image files and reminder delivery records. If an older omd tab blocks the
upgrade, save and close that tab before retrying. Notebook JSON remains compatible.
URLs do not transfer notebook data: the target
page must exist in the same browser profile and origin. The hosted app remains
on the version deployed from `main`; publishing this release does not merge its
changes or update GitHub Pages.

## Download and run

Download **omd-v0.0.4.zip** or **omd-v0.0.4.tar.gz**, then extract the entire archive.
These packages include the compiled app, browser libraries, fonts, styles, icons
and third-party notices. No npm install, build step or runtime CDN is required.
Use these named packages, not GitHub's automatically generated source archives.

With **Node.js 22+** installed, run in the extracted folder:

    node start.mjs

Open **http://localhost:3000/**. The package is platform independent; Node and
the browser are prerequisites. Static HTTP/HTTPS hosting is also supported;
configure a document fallback for page routes if the host does not use `404.html`.
Use **SHA256SUMS.txt** to verify the two packages.

Data stays in browser storage. JSON export/import transfers notebooks between
origins or devices. Notifications need permission and a running app; WebMCP needs
native browser/extension support.

## Verification

The application source passed 111 unit tests and both push/PR CI workflows
(7 jobs each). Chromium and WebKit regressions cover root and `/omd` hosting,
input transfer, native IndexedDB migration/recovery, diagrams, scene/image/font
loading, import/export and offline use. Native page routes also passed five runs
at each path with CPU slowdown. Release packaging verifies the extracted ZIP
and tar.gz launchers and bundled assets without `node_modules`.

See [ticket fixes and dependency verification](../ticket-resolution.md) for exact
versions, reproduction evidence and the limits of Linux browser/IME verification.
