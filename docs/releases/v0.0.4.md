# omd v0.0.4

Fourth release of **oh my day**, a local-first notebook. Changes since v0.0.3:

- **Independent browser tabs:** each tab keeps its own selected page while
  notebook edits continue to synchronize through IndexedDB and BroadcastChannel.
  Selecting a page no longer changes the content revision or undo history.
- **Page links:** every page has a stable `/page/:id` route (`/omd/page/:id` on
  the hosted app). Copied links, refresh, browser Back/Forward and opening page
  links in a new tab retain the selected page, including subpages.
- **Safe navigation:** pending edits save before switching pages. Missing,
  deleted or replaced page IDs fall back to an existing page with a notice,
  without creating a fake page or redirecting edits to another page.
- **Deep-link hosting:** the local launcher serves page document routes, the
  build includes a GitHub Pages `404.html` fallback, and the service worker can
  reopen page links offline. Missing script/style assets remain errors.

Notebook JSON remains compatible. URLs do not transfer notebook data: the target
page must exist in the same browser profile and origin. The hosted app remains
on the version deployed from `main`; publishing this release does not merge its
changes or update GitHub Pages.

## Download and run

Download **omd-v0.0.4.zip** or **omd-v0.0.4.tar.gz**, then extract the entire archive.
These packages include the compiled app, browser libraries, fonts, styles, icons
and third-party notices. No npm install, build step or runtime CDN is required.
Use these named packages, not GitHub's automatically generated source archives.

With **Node.js 22+** installed, run in the extracted folder:

    node start.mjs

Open **http://localhost:3000/**. The package is platform independent; Node and
the browser are prerequisites. Static HTTP/HTTPS hosting is also supported;
configure a document fallback for page routes if the host does not use `404.html`.
Use **SHA256SUMS.txt** to verify the two packages.

Data stays in browser storage. JSON export/import transfers notebooks between
origins or devices. Notifications need permission and a running app; WebMCP needs
native browser/extension support.
