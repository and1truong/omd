# omd v0.0.7

This release adds callouts and keyboard-first block creation to **oh my day**,
including the browser app and the desktop preview. Changes since v0.0.6:

- **Callout blocks:** highlight Markdown notes with an editable icon and Neutral,
  Info, Success, Warning or Danger backgrounds. The color selector appears on
  hover, with keyboard focus and touch access. Callouts work inside nested
  containers and retain their text, icon and color through reload, JSON backups
  and undo/redo.
- **Slash commands:** type `/` at the start of a plain text block to open the
  block menu beside the caret. Type to filter, use ↑/↓ to choose, and press
  Enter or Tab to create the selected block in the same position. Escape closes
  the menu without changing the text. The menu respects nested tab limits and
  avoids code, checklist items and unfinished IME composition.
- **Safe conversion:** the slash command preserves the block ID and sibling
  order in one durable operation. Undo restores the command paragraph, stale
  edits are rejected, and a failed save keeps the editor available for retry.

These changes include PRs #57 and #58. Existing notebook JSON and IndexedDB
formats are unchanged; import/export remains the way to transfer notebooks
between browser and desktop storage profiles.

## Choose a download

| Platform/use | Asset |
| --- | --- |
| Linux desktop | `OMD_0.0.7_*.deb` |
| macOS desktop | `OMD_0.0.7_*.dmg` |
| Windows desktop | `OMD_0.0.7_*-setup.exe` |
| Browser/local server | `omd-v0.0.7.zip` or `omd-v0.0.7.tar.gz` |
| Lime for Chrome/Edge | `orchard-lime-extension-0.1.0.zip` |

Desktop installers bundle their runtime; users do not need Node/npm for the
installed app. They remain unsigned previews without notarization or automatic
updates. The Orchard host and Lime extension remain pinned to `orchard-v0.1.0`.

For the web archive, extract the entire package and run `node start.mjs` with
Node 22+, then open http://localhost:3000/. The compiled app, libraries, fonts
and offline assets are included. GitHub's automatic source archives require a
build; use the named release packages to run the app.

Verify downloads with `SHA256SUMS.txt`. `omd-desktop-builds.json` records the
platform, runtime and Orchard provenance of the desktop builds.

Ordinary editing needs no agent credentials. Agent features require a configured
gateway and user consent/approval. Keep JSON exports as backups; reminders run
while OMD is open and catch up when reopened.

## Verification

The release pipeline checks strict types, source tests, browser behavior and
callout/slash regressions at `/` and `/omd/`, static/offline asset completeness,
and extracted web packages. Publication also requires all three desktop
installers, native policy tests, Linux native and installed-package acceptance,
and browser Bridge/Lime integration. Checksums and build provenance are verified
before the tag and complete asset set are published.
