# omd v0.0.8

This release adds a Cloudflare edition and drag-to-column layouts to **oh my day**.
It includes merged PRs #59 and #60. Changes since v0.0.7:

- **Drag to columns:** drag a block to the left or right edge of another block
  to create a column on that side. Existing rows expand up to 12 columns. A
  visible line previews insertion, and Escape cancels the drag. Each column
  holds multiple vertically ordered blocks; empty columns disappear and
  single-column rows unwrap. Columns stack on small screens.
- **Durable layouts:** pending drafts save before moving; stable block IDs,
  Undo/Redo, JSON backups, browser/desktop storage and Cloudflare D1 retain the
  layout. The existing WebMCP `move_block` tool supports left/right edge moves.
- **Cloudflare edition:** deploy the compiled frontend and Worker with D1
  migrations and a pinned Wrangler setup. Notebook edits persist in D1 and
  synchronize between browsers. Revision checks reject stale edits; failed
  saves retain drafts, and retries safely recover acknowledged writes.
- **Shared notebook without login:** the Cloudflare edition intentionally has
  no authentication. Anyone who can open its URL can read and edit the same
  notebook. It requires a connection; browser and desktop editions retain their
  local storage and offline behavior.
- **Reliability fixes:** Cloudflare reminder delivery, concurrent updates,
  notification settings, large records, import/history operations and recovery
  after connection errors are covered by real Worker/D1 tests. Native controls
  wait for pending edits, and callout color controls stay clear of column text.

## Choose a download

| Edition/platform | Asset |
| --- | --- |
| Browser/local server | `omd-v0.0.8.zip` or `omd-v0.0.8.tar.gz` |
| Cloudflare Worker + D1 | `omd-cloudflare-v0.0.8.zip` or `omd-cloudflare-v0.0.8.tar.gz` |
| Linux desktop | `OMD_0.0.8_amd64.deb` |
| macOS desktop (Apple Silicon) | `OMD_0.0.8_aarch64.dmg` |
| Windows desktop | `OMD_0.0.8_x64-setup.exe` |
| Lime for Chrome/Edge | `orchard-lime-extension-0.1.0.zip` |

For the **browser** edition, extract the entire archive and run `node start.mjs`
with Node.js 22+, then open http://localhost:3000/. Compiled libraries, fonts,
offline assets and third-party notices are included; no build is required.

For **Cloudflare**, extract its separate archive and follow the included README:
install the pinned deployment dependencies, create a D1 database, set its ID in
`wrangler.jsonc`, apply migrations and deploy. A Cloudflare account and deployment
credentials are needed by the operator; notebook visitors do not log in.
[Cloudflare deployment guide](https://github.com/and1truong/omd/blob/v0.0.8/docs/cloudflare.md).

Desktop installers bundle their runtime; Node/npm is not required for the
installed app. They remain unsigned previews without notarization or automatic
updates. Orchard/Lime remains pinned to `orchard-v0.1.0`.
[Desktop setup and data guide](https://github.com/and1truong/omd/blob/v0.0.8/docs/desktop.md).

Use the named release packages to run the app; GitHub's automatic source archives
require a build. Verify downloads with `SHA256SUMS.txt`.
`omd-desktop-builds.json` records desktop build provenance.

## Data and compatibility

Export notebook JSON before moving between editions or origins. Browser and
desktop profiles keep separate local notebooks; the Cloudflare edition stores
one shared notebook per deployment. Pages containing column layouts require
v0.0.8 or newer; older app builds cannot read that new block type. Keep JSON
exports as backups. Reminders run while OMD is open and catch up when reopened.

## Verification

Publication requires strict types, 146 source tests, native browser regressions
at `/` and `/omd/` including callouts, slash commands and column dragging, static
and offline asset validation, real Worker/D1 tests and extracted browser and
Cloudflare package checks. All three desktop installers, native policy tests,
Linux native/installed-package acceptance and browser Bridge/Lime checks must
also pass. The pipeline verifies checksums and provenance before publishing the
tag and complete asset set.

Both feature PRs completed GitHub Codex review without remaining findings.
